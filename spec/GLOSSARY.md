# Glossary

Terms used across RSOS and the [roadmap](ROADMAP.md), each defined so it can be measured or built. Terms already defined in their own specs link there.

| Term | Definition |
|---|---|
| Anchor | A stored pairing between a cue (vibration code, scent, light, phrase, glyph) and a state, captured at a measured moment, with a role and a measured strength. The roadmap's central object (items 1, 21, 22) |
| Anchor strength | The measured change a cue produces when played alone, for example in heart rate or heart rate variability, with an interval |
| Probe trial | A test in which the cue is played alone, with nothing else, to measure the anchor's strength |
| Contamination | An anchor that has taken on the meaning of a stressor because it was used while the stressor was present; seen as its effect turning negative (item 66) |
| Restoration | Re-pairing a contaminated anchor with a resource until its effect is positive again |
| Anchor role | What an anchor does in a chain: healing, stability, redirection or lock-in |
| Anchor chain | Anchors played in sequence, each phase with its own check that it worked (item 22) |
| Anchor tree | A central image with context images fixed to its parts, each with its own code (item 11) |
| Attachment point | A named region of a glyph, or of the body, that holds a context image or a cue |
| Code | A glyph's vibration rhythm in short and long pulses; see [GLYPH_FORMAT.md](GLYPH_FORMAT.md) §7 |
| Code family | Codes that share a prefix, one family per learning area (item 6) |
| Composite glyph | Two glyphs held as one, such as Tier 013 🦁 + 🐉 (item 68) |
| Node | A desired state held as one unit; see [NODES.md](NODES.md). In the trigger atlas, a node is a trigger (an object, sound, smell, place or thought) |
| Tier | A record of the tier ledger; see [TIER_LEDGER.md](TIER_LEDGER.md) |
| Override | The protocolised interrupt, resource and future-pacing sequence; see [OVERRIDE_PROTOCOL.md](OVERRIDE_PROTOCOL.md) |
| Future-pacing | Rehearsing the new response in an imagined future situation |
| Identity profile | A whole identity held as a profile: a symbol, a level tree, anchors, a language, an environment, policies and a dose (items 23, 35) |
| Level | One layer of identity: environment, behaviour, capability, beliefs and values, identity, purpose (after Dilts and Hall) |
| Level classifier | Decides which level a sentence comes from (item 13) |
| Login code | The code that activates an identity profile |
| Global interrupt | The override that works in every profile ("I move. I act.") |
| Coherence score | How consistently a person's reactions match a profile's values over time |
| Drift | Movement away from a profile, measured with the coherence score |
| Autonomy gate | CONTAIN's rule that an anchor may fire on its own only after manual training, proven strength, few false alarms and no wear-out (item 26) |
| Wear-out | Loss of a cue's strength from appearing too often outside training (item 4) |
| Trigger atlas | A weighted graph of what shifts a person's state, built from a period of mapping (item 57) |
| Combined node | A trigger that acts only in combination, such as a sound with one object but not another (item 59) |
| Map readiness | Whether each node has enough exposures for its weight to be stable (item 61) |
| Transfer | Change in nodes or activities that were never treated |
| Transfer test | Measuring reactivity on untreated nodes after one node is treated |
| Transfer engine | Chooses the node to treat, by weight or by level, and runs the transfer test (item 63) |
| SSIT | Superordinate-to-Subordinate Imagery Transfer: imagery about a higher node, flowing down to the levels below (items 63-65) |
| Network trance | The trance technique that works on the biggest node across the senses (item 60) |
| Personal trial | A randomised single-case experiment (N-of-1) in which conditions are chosen at random for one person (item 33) |
| Sham anchor | A cue never paired with the state, used as a control in personal trials |
| CHECKS | Built-in cognitive tests (item 48) |
| DOL-9 | The daily override loop specified by the old assistant (item 50) |
| OXQ | Override Execution Quotient: overrides divided by waking hours, times 100 (item 50) |
| Claim event | A claim found in the design records, recorded with its source and the test it becomes; see [CLAIMS.md](CLAIMS.md) |
| Re-entry event | Assistant text reused as the seed of a later design record |
| Protocol kit | Study design, consent wording, data format, analysis code and report template for running a module with real instruments |
| Simulation labels | *Built and tested in simulation* (the machinery works) and *effect unproven in people* (what needs a real study) |
