# CONTAIN — Safety and governance

**Function:** Governs every module: allow, block, roll back or quarantine actions; drift control; human in the loop; device safety envelope.

**Status:** **Built** — working, tested code in this repository

**Now:** Built (`spec/CONTAIN.md`, `rsso/rsso/contain.py`, identically `docs/js/contain.js`, safety page `docs/safety.html`): the policy engine the archive names but does not recover. A device safety envelope no program can exceed (vibration strength, pulse and pattern length, total vibration, tone pitch and length, scent and taste per run, run length, offer limits); drift detection that pauses (quarantines) a program or node when distress after it rises, agency falls, or it is stopped often together with another signal, and at once when an adverse event is linked to it; escalation that pauses device offers and therapist-led work and points to a therapist or crisis help after a serious adverse event, repeated moderate ones, a positive screening answer or repeated high distress; one decide() gate that the player, the heart-rate offers, the node studio and the Python runtime ask before acting, with every decision logged with its reason; restore by the person, or by the therapist when harm was involved; rollback to the previous approved node plan. Also: the RSX compile-time haptic limit, `SafetyGovernor` run limits, the runtime intensity clamp and Stop in every phase. Conformance C14 (envelope) and C15 (drift pause and restore), 15/15 on the virtual rig and the firmware core; the CONTAIN twins in the cue engine guard against misleading self-reports.
