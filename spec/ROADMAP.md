# RSOS roadmap

The findings from a review of the RSOS design records (2023-2025), turned into a build plan. Generated by `architecture/roadmap.py`; do not edit by hand. The claims register is in [CLAIMS.md](CLAIMS.md); prior art, glossary, foundations and the provenance of names are in [PRIOR_ART.md](PRIOR_ART.md), [GLOSSARY.md](GLOSSARY.md), [FOUNDATIONS.md](FOUNDATIONS.md) and [PROVENANCE.md](PROVENANCE.md).

## The core finding

One operator holds across three years of the design records: change a central node, and the change spreads to everything connected to it. The repository already has the output side (programs, devices, glyphs, safety). The design records add anchors as measured, programmable objects; the input side, mapping a person's triggers and states; and rigour built in, so every claim can be tested inside the product.

## The standard every step meets

- Simulation first, with known answers; ready for real hardware without other changes.
- Tests, with Python and browser versions giving identical results; a spec for each module.
- A protocol kit (study design, consent, data format, analysis code, report template) for clinicians, labs, universities and companies.
- Two labels on everything: *built and tested in simulation* and *effect unproven in people*.
- The site's design: one signature visual per page, motion only when it means something, phone first, offline, accessible; screenshots checked before release.
