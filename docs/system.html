How a negative state becomes an override, and the override a reflex

One loop runs through every part of RSOS. A trigger arrives through the senses, the body or a sensor; safety decides whether anything may start; the RSX program plays the tier's bundle through every channel; memory records what happened and learns. Select any part to see what it does, how far it is built, and which tiers of the ledger live there.

The channels

Each tier is a bundle: one cue per channel, learned and later triggered as one unit. The same channels carry triggers in and the override out.

Where the tiers live

Tier records by subsystem and channel. Select a number to see those tiers. Placement is by hand for the override-practice tiers and by keyword rule for the rest; the tier ledger page shows which, and why. No tier in the ledger names smell or taste: those two channels come from the tier-bundle design (RSIA) and the device protocol, not from the ledger.

What the system does when it responds

The ledger recorded how the system behaved at each tier (as “GPT Behavior”). Those behaviours reduce to a small set of responses, which the AI, BCI and device layers perform.

Statuses come from the architecture map (architecture/build.py): built, complete in simulation (tested with virtual devices and participants, waiting for real hardware and people), partly built, specified. Data: tier_map.json.
