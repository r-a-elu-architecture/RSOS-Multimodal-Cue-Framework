## Reported beside the tests (not pass conditions)

- **Per conversation.** R1: 15% of conversations contain any re-entry. Notes re-entry is above the baseline in 86% of
  conversations, phrases in 53%, melody inheritance in 89%.
- **GPT-3.5 vs GPT-4.** R1 re-entry is higher with GPT-4 (9.5% vs 3.9%), as are notes (0.276 vs 0.255) and phrases (0.046
  vs 0.032). **Melody re-entry reverses with GPT-4** (0.54 against a baseline of 0.67; GPT-3.5 0.74 against 0.69), so the
  pooled melody re-entry pass is small (+0.015) and not uniform; it should not be read as robust. Inheritance holds for
  both (0.81 vs 0.56 and 0.72 vs 0.45).
- **Length bands (user turns 3–4 / 5–9 / ≥ 10).** R1 5.9% / 5.3% / 3.7%: re-entry is somewhat less frequent per turn in
  long conversations.
- **C2 robustness (exploratory).** Families are blocks of ≥ 150 words a user pasted again, with edits, across their
  conversations. 84% of the 467 families with a defined per-family ρ show a positive ρ (mean 0.38; sign test p ≈ 10⁻⁵¹).
  Without the 20 families of more than 20 members, ρ = 0.17. A user here is an IP-plus-browser pair, an approximation:
  shared networks can merge people and changing networks can split one person.
- **C5.** 85% of the 992 boundary events are followed by a long non-refusing reply within two replies, whatever the
  user's next move. The reframing type does not predict that change on the held-out users (AUC 0.49). The lexical
  boundary detector also matches replies that only point to help resources, so this measures a mix of refusals and
  hand-offs.

## Operational notes, disclosed

- **No Parquet library was available** (no network for installs). A minimal pure-Python reader was written
  (`parquet_min.py`: Thrift footer, Snappy, PLAIN and dictionary encodings) and checked against the file structure
  before any analysis.
- **Fast path, checked.** Units are hashed (64-bit mixing hash over word ids) so the 2000 redraws can run vectorised. The
  hashed path was checked against the plain-Python definitions of `mse.py` and `corpus_lineage_v2.py` on 3,000 sampled
  true pairs (R1, notes, phrases, both carry-forwards) and 3,000 random cross-conversation pairs (notes, phrases): 0
  mismatches. Melody, R3, C2 and C5 run in plain Python.
- **C2 computation.** Drift is symmetric in its two arguments, so each family's drift matrix is computed once and each
  shuffle reassigns generation positions. This is the same test as recomputing drift on the shuffled family.
- **Timing seeds.** Run-time checks used seeds 777777 and 900000–900001, outside the registered seeds; their outputs were
  deleted.

## What this shows and what it does not

The output-becomes-input structure first found in one long private record also appears in 22,369 public conversations
with two models. Users reuse the assistant's words and phrases. The reused material reappears in the next reply more
than the user's own words do. Replies inherit the shape of the previous reply. Blocks a user pastes again across
conversations drift further from their first version the more generations apart they are. In LSGPA terms, one generation
becomes the next generation's input, and that input carries forward.

It does not show causation: R3 compares re-entered words with the user's other words in the same turn, which controls
for topic only in part. It says nothing about the agents or models of §11.1–11.10. The sample is 3 of 14 shards,
English, with at least 3 user turns.

## Next test (proposed)

1. **Confirmation on shards 3–13** (about 615,000 further conversations), with the same code, fresh seeds and the same
   thresholds, registered before opening.
2. **Second dataset:** LMSYS-Chat-1M (a different interface and user base, and more models) for R1, R3 and MSE.
3. **Causal probe of carry-forward:** within a conversation, compare replies to user turns that quote the previous reply
   with matched turns that paraphrase the same content (same content words, no verbatim span). This separates
   verbatim re-entry from topic.
