# Applications and implementation boundaries

## 1. Mnemonic glyphs and context-aware learning prompts

**Example:** A consenting person assigns a mnemonic symbol to a communication principle. A voluntary session can suggest the symbol in a chosen context, optionally with an audio cue or a brief future-context rehearsal. Tests should measure delayed recall and task latency, not inferred belief installation.

## 2. Configurable cue programs

A user can build interrupt → chosen resource cue → breath → future rehearsal, or a single swish-style imagery prompt, or a neutral mnemonic. Tiers and modalities are optional. The compiler must reject unknown operators, unintended cycles and missing permissions.

## 3. BCI and physiology

Recorded EEG/HRV may inform signal quality or calibrated task states. There is **no validated emotion decoder** or verified clinical effect in this project. Hardware-in-the-loop testing is a future workstream.

## 4. Adaptive learning and training

Calibrate cues on user-approved tasks, compare fixed versus individualized and equally informed generic adaptive policies, and test transfer to unseen contexts.

## 5. VR/AR and accessible interfaces

VR/AR overlays can present personally defined glyphs or mnemonic reminders with opt-in controls. Eye tracking, audio and haptics are potential interface channels, not proof of counterconditioning.

## 6. Research security

Provenance-aware execution checks whether a source-targeted cue program is authorized and has an auditable ancestry. Use signed proofs carefully: the original project found that strong generic graph-proof controllers can match RSOS exactly.

**Current status:** executable software research and synthetic evaluations; no demonstrated treatment efficacy. See [benchmarks](BENCHMARKS.md).
