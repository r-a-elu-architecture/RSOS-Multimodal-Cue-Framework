# What can this configurable framework actually do?

| Module example | User-programmed behavior | Benchmarked now | Still missing |
|---|---|---|---|
| Private social-context mnemonic | User marks context; image+sound suggests a privately registered memory cue | Context/consent/quality contract and offline demo | Real-time permitted context classifier, recognition/recall study |
| Color-triggered self-chosen cue | User marks color; interruption glyph → resource image → optional rehearsal | Graph compiler, authorization, branch pause | Human cue-pairing calibration and delayed response tests |
| Tier 1–10 program | Optional labeled stages for one self-chosen task | Valid tier interval compilation | No proof that numeric tiers correlate with internal states |
| Tier 1–20 module or non-tier module | Different module shares the same runtime, no global max | Randomized interval compilation and no-tier tests | User workflow studies |
| Swish-style self-directed imagery | One optional operator, no compulsory full ritual | Program compilation and permission checks | Any real psychological outcome; not clinical intervention |
| Neurological-level goal map | User-declared environment, skills, values, mission etc attached to program | Validated schema only | Objective independent criteria for goal attainment |
| Wearable/VR display path | Offline signal-quality gate and visual/sound cue plan | Synthetic FFT test; routing tests | Real EEG data, latency and artifact benchmarking on target hardware |
| Laboratory cue learning study | Randomize and compare user-defined glyph/audio sets and contexts | Simulated preference-test harness | Human subjects, ethical oversight, blinded follow-up outcomes |

## Comparison with existing methods

The framework's modularity does not establish competitive advantage over existing adaptive apps, user-personalized mnemonic software, graphical workflow engines or neurofeedback products. Just-in-time adaptive interventions already use user input, contextual features and automated cueing. BrainFlow already supplies multiple hardware adapters and synthetic/playback boards. A new public claim would require comparing usable device integration, quality of cue calibration, and **prospectively measured objective learning/recall outcomes**, including a matched generic controller.
